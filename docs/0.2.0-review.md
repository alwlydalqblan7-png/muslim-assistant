## Changes and preservation
- Full offline Quran reader, index/search, 12-verse chunks, local reading position/font persistence; migrates old short-surah selection without deleting preferences.
- Foreground adhan playback with audio focus, stop action, completion/error cleanup, finite timeout. Old voice choice remains saved; unavailable Makkah/Madinah voices are not silently replaced.
- Prayer alarms exact only with user permission; inexact notification-only fallback. Automatic audio requires chosen licensed voice, prayer notifications, adhan enabled, permission, and a recent alarm.
- Reschedule after boot, app update, clock/zone changes and foreground resume.
- Shared prayer timeline used by UI and scheduler; offsets preserve the date boundary.
- Opening app no longer postpones hourly dhikr; quiet hours 22–07 preserved; suppress dhikr near prayer/playing adhan. Dhikr sound is a notification tone, not a spoken recording.
- Fix first counter tap around midnight; retain all existing keys, cities, defaults, official icons, and other screens.

## Signing — installation gate
Existing CI generates disposable debug keys. APK certificates cannot recover private keys. No applicationId change or removal of user data is performed.
Gradle now accepts MUSLIM_SIGNING_STORE, MUSLIM_SIGNING_STORE_PASSWORD, MUSLIM_SIGNING_ALIAS, MUSLIM_SIGNING_KEY_PASSWORD. Workflow can restore the matching existing key from MUSLIM_SIGNING_STORE_BASE64 secret. Never commit a keystore or passwords.
Without those secrets the resulting debug APK is a test candidate, not a compatible update promise. Compare its certificate with the actual installed APK. Obtain the original keystore if it exists; otherwise stop installation and plan a data-preserving migration with the user. Do not suggest uninstall as a default.
